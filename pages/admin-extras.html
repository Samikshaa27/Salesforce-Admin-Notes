Admin Extras

The admin topics that sit between the other pages: standard profile names, dependent picklists, global actions, email templates and alerts, the lead process, Flow trade-offs, and the order of execution from an admin's point of view.

Standard profile names

Profile What it is
System Administrator Full control: Modify All Data, View Setup, customize the application. Keep the number of these small.
Standard User Create and edit records they own across most standard objects; no setup access.
Read Only View records and run reports, no create or edit.
Solution Manager Standard User plus the ability to manage published solutions.
Marketing User Standard User plus campaigns, lead import and campaign setup.
Contract Manager Standard User plus create, edit, approve and activate contracts.
Standard Platform User Platform licence: custom objects and a limited set of standard objects (no Leads or Opportunities).
Chatter Free / Chatter Only / Chatter Moderator Collaboration-only profiles for users who don't need CRM data.
Community profiles Customer Community, Customer Community Plus, Partner Community and Guest (site) profiles for Experience Cloud users.
🔑
Clone, don't edit Most permissions on standard profiles are locked. Clone the nearest one, or keep a minimal profile and layer permission sets and permission set groups on top.

Dependent picklists & field dependency

Controlling field

A picklist or checkbox whose value decides which values appear in another field. Example: Country.

Dependent field

A picklist or multi-select picklist whose available values depend on the controlling field. Example: State.

  • Create both fields first (Object Manager → Fields & Relationships).
  • Open Field Dependencies → New, choose the controlling and dependent field.
  • Use the matrix — select the dependent values and click Include Values for each controlling value.
  • Check record types — the values must also be enabled on the record type, or users won't see them.
⚠️
The dependency is a UI filter Don't assume it stops bad values arriving through imports or the API. If the pairing must hold, make the picklist restricted and add a validation rule. A controlling field supports up to 300 values.

Multi-select picklist

Stores several values in one field, separated by semicolons. Filter with INCLUDES, and avoid it where you need clean reporting. Prefer a junction object or checkboxes when the data will be analysed.

Email templates & email alerts

Email templates

Type Use
Text Plain text, simplest and most compatible.
HTML with letterhead Classic template that wraps content in a branded letterhead.
Custom HTML Your own HTML, no letterhead.
Visualforce Full control and logic; developer-built.
Lightning Email Template Built in the Lightning template builder, with rich text, images and related-object merge fields.

Merge fields pull record data into the message. Classic templates use {!Contact.FirstName}; Lightning templates use {{{Recipient.FirstName}}}. Templates live in folders, and folder access decides who can use them.

Email alerts

  • An email alert is an action that sends an email from a template when something fires it.
  • Fired by record-triggered Flows, approval processes, escalation rules and legacy workflow rules.
  • Recipients can be users, roles, public groups, an email field on the record, the owner, or a few typed addresses.
  • From address can be an Org-Wide Email Address, so replies go to a shared inbox.
  • Daily send limits apply and scale with licences, so check them before a bulk notification.

Lead process

Lead lifecycle

Lead → customer

Capture (Web-to-Lead, import, manual) → Assign (assignment rule, queue) → Nurture (campaigns, follow-up) → Qualify (status moves to a converted value) → Convert (Account + Contact + Opportunity).

Lead process (configuration)

Defines which Lead Status values are available for a record type. Different record types can use different processes.

Lead conversion

Creates an Account, a Contact and optionally an Opportunity, and carries lead data across using the lead field mapping.

📝
Converted status At least one Lead Status value must be marked Converted, otherwise leads can't be converted. Converted leads become read-only. Check duplicate rules first so conversion attaches to the existing Account or Contact instead of creating copies.

Related pages: Web-to-Lead, Assignment rules, Duplicate rules, Lead → Cash.

Flows: advantages & limitations

Advantages

Declarative, covers most automation, and replaces Workflow Rules and Process Builder (both retired). Built-in debugging, versions, and fast before-save updates on the same record.

Limitations

Same per-transaction governor limits as Apex. Heavy bulk logic and complex algorithms are easier in code. Several flows on one object need a defined trigger order.

Limit / trap What to do
100 SOQL queries and 150 DML statements per transaction Never put Get Records or DML elements inside a loop; collect, then act once.
2,000 executed elements per interview Simplify loops, or move heavy work to an asynchronous path or Apex.
Order of record-triggered flows isn't guaranteed Set a trigger order or combine into one flow per object and event.
Unhandled errors roll back the save Add fault paths and notify an admin.

Types, elements and best practices are on the Flow Builder (Deep) page.

Order of execution (admin view)

When a record is saved, Salesforce runs automation in this sequence:

  • 1. Load the record and run system validation (required fields, formats, lengths).
  • 2. Before-save record-triggered flows.
  • 3. Before triggers (Apex).
  • 4. System validation again, then custom validation rules.
  • 5. Duplicate rules.
  • 6. Record saved to the database (not yet committed).
  • 7. After triggers (Apex).
  • 8. Assignment rules, then auto-response rules.
  • 9. Workflow rules (legacy), then escalation rules.
  • 10. After-save record-triggered flows (and legacy processes).
  • 11. Entitlement rules.
  • 12. Roll-up summary and cross-object formula updates on parent records, then sharing evaluation.
  • 13. Commit, then post-commit work (emails, async jobs).
⚠️
What isn't guaranteed The order of multiple triggers on one object, or multiple flows of the same type, isn't guaranteed unless you set a trigger order. Developer detail is on Triggers & Order of Execution.

Interview questions

1 What is the difference between a profile and a permission set?Medium

Every user has exactly one profile, which sets the baseline: object and field access, app and tab visibility, record type and layout assignment, login hours and IP ranges. Permission sets only add access on top, and a user can have many. Salesforce recommends keeping profiles minimal and granting access through permission sets and permission set groups.

2 A user can't see a value in a dependent picklist. What do you check?Medium

First the field dependency matrix (is the value included for the chosen controlling value?), then the record type (is the value enabled there?), then field-level security on both fields and whether the controlling field is on the layout.

3 What's the difference between a quick action and a global action?Medium

An object-specific action belongs to one object and inherits context, so records it creates are automatically related. A global action isn't tied to an object and creates standalone records. Global actions go in the global publisher layout; object actions go in the page layout.

4 A validation rule blocks a record that an assignment rule should have routed. Which runs first?Hard

The validation rule. Custom validation runs before the save, and assignment rules run after it. If validation fails, the save stops and assignment never happens.

5 Why might a Flow fail only on a bulk data load?Hard

Governor limits are per transaction, and a data load processes up to 200 records at once. A Get Records or DML element inside a loop works for one record but exceeds the 100 SOQL or 150 DML limit for a batch. Move the query or update outside the loop and work on collections.

Quick check

1. You need to set the State picklist based on the Country picklist. What do you create?
A controlling picklist filters the values in a dependent picklist. Add a validation rule too if API loads must be enforced.
2. Which runs first when a record is saved?
Before-save flows run first, then before triggers, validation, duplicate rules, the save itself, and only then assignment rules and after-save flows.
3. Which lead setting controls which Lead Status values a record type can use?
A lead process lists the Lead Status values available per record type. Field mapping only controls what carries over at conversion.
